# ADR 0002: teleproto и текст статей Telegram

**Статус:** реализовано 23 сентября 2026 года.

**Источники:** [package.json](../../package.json), [клиент](../../src/worker/client.ts), [извлечение текста](../../src/worker/message-content.ts), [сборщик](../../src/worker/collector.ts), [восстановление](../../scripts/backfill-articles.ts).

## Контекст

Старый Telegram-клиент на слое API 198 получал новые статьи как `MessageMediaUnsupported` с пустым `message`. Сборщик сохранял только `message`, поэтому публикация могла иметь счётчики, но не иметь текста в TgMon. AI-маршруты summary/super-report исключают записи с `text=null`, что приводило к неполной текстовой выборке.

Нужно получать содержимое через MTProto, сохранить существующую сессию и пути импортов, включить текст в текущие интерфейс и аналитику, а также восстановить старые пропуски без дублирования постов.

## Решение

1. Зависимость `telegram` закреплена как npm alias `npm:teleproto@1.229.0` со слоем API 229. Импорты `telegram` и `telegram/sessions` сохранены; настройка `serverExternalPackages: ['telegram']` в Next.js остаётся применимой. Удалён отсутствующий в новом клиенте параметр `useWSS`.
2. `readMessageContent` использует `Rich.toPlainText` для `richMessage`. Если Telegram пометил статью `part=true`, выполняется `getRichMessage` с существующими rate-limit/retry/timeout. Обычный текст и подписи остаются в прежнем пути обработки.
3. Полный полученный текст сохраняется в `Post.text`. Отдельная модель статьи, хранение HTML, загрузка изображений и OCR не вводятся; миграция БД не требуется.
4. При ошибке догрузки возвращаются `text=null` и `available=false`. Upsert обновляет доступные счётчики, но сохраняет прежние текст и `isAd`; сборщик не заменяет упоминания неполным результатом и продолжает обработку следующих сообщений.
5. `extractPostMentions` используется обычным сбором и утилитой восстановления. Реклама определяется из того же полученного текста.
6. `backfill-articles.ts` обрабатывает пустые записи одного канала. Dry-run — режим по умолчанию; `--apply` транзакционно обновляет текст, рекламный флаг и упоминания. Проверка пустого текста повторяется при записи, чтобы не затереть результат параллельного сборщика.

## Альтернативы и компромиссы

- Сохранение старого клиента и замена подписи в UI не возвращают содержание, необходимое анализу.
- Публичное веб-превью не используется как источник: сборщик продолжает работать через авторизованный MTProto-клиент, включая доступные ему приватные каналы.
- Хранение дерева rich-блоков и собственный рендерер позволили бы точнее воспроизвести оформление и медиа, но потребовали бы нового контракта хранения и отображения. В текущей реализации выбран обычный текст.
- Alias уменьшает объём замены импортов, но имя `telegram` теперь обозначает teleproto. Версию нужно проверять по package.json/lockfile; обновление клиента требует проверки всех MTProto-потоков, а не только статей.

## Последствия и эксплуатация

- Новые тексты доступны карточкам, поиску, рекламе, упоминаниям и AI в пределах существующих временных окон и лимитов. Сохранённые AI-отчёты не пересчитываются автоматически.
- Обычный сбор обновляет до 200 последних сообщений; более старые пустые статьи восстанавливаются отдельной утилитой. Для недоступных сообщений содержание не придумывается.
- Признак статьи, статус догрузки и её исходные rich-блоки в БД не хранятся. Подпись «Текст недоступен» не различает медиа без подписи, неподдерживаемый формат и пропуск сбора.
- Требуется обновление обоих Docker-образов: worker собирает по расписанию, web — при добавлении канала и ручном сборе. Возврат к старому клиенту прекращает поддержку статей; это не откат уже восстановленных текстов.

## Проверка

Тесты: [message-content.test.ts](../../src/worker/__tests__/message-content.test.ts) — обычный текст, блоки статей, догрузка и сбои; [article-collection.test.ts](../../src/worker/__tests__/article-collection.test.ts) — сохранение, реклама, упоминания и продолжение сбора после ошибки.

В ходе внедрения проверены чтение статьи существующей сессией, восстановление с повторным dry-run, сбор в Docker и открытие полного текста через браузер. Эти проверки относятся к внедрению, а не гарантируют доступность любого сообщения Telegram. Порядок повторения — в [эксплуатации](../deployment.md) и [инструкции восстановления](../../scripts/README.md#восстановление-текста-статей).
