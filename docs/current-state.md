# Текущее состояние и передача работы

Снимок: 28 октября 2026 года. Рабочая ветка `main`; серверный web-образ собран из `e581c4e`. Перед следующей задачей проверить Git и состояние сервера заново. Этот документ фиксирует выполненные проверки, а не постоянную гарантию доступности сервиса.

## Реализовано

- Новые пользователи входят через Telegram OpenID Connect, получают заявку `PENDING` и ждут решения администратора. В `/settings` администратор может одобрить, удалить ожидающую заявку, заблокировать аккаунт или вернуть заблокированный аккаунт в заявки. Прежние аккаунты с паролем сохраняются и могут привязать Telegram.
- Исправлены возврат callback на публичный домен и обмен кода на токен: запрос содержит `client_id`, а HTTP Basic формируется из исходных Client ID и Secret. Это устранило `invalid_client`, вызванный дополнительным форм-кодированием одного символа Secret библиотекой.
- Папка `backups/` исключена из Docker-контекста, чтобы резервные копии сервера не попадали в web-образ.

## Проверки и эксплуатация

- До последнего исправления полный `npm test -- --maxWorkers=2 --reporter=dot` прошёл: 123 файла, 765 тестов. После исправления HTTP Basic прошли ближайшие 7 тестов, `npx tsc --noEmit` и ESLint затронутых файлов. GitHub CI для `e581c4e` завершился успешно, включая полный набор тестов и сборку.
- На сервере выполнен fast-forward до `e581c4e`, пересобран и пересоздан только web. Production-сборка завершилась успешно, `/api/health` ответил 200, callback без flow-cookie перенаправил на публичный `tgmons.online`. Worker и PostgreSQL не пересоздавались; `backups/` сохранён.
- После обновления пользователь прошёл Telegram-вход и увидел страницу «Заявка отправлена». Read-only проверка БД показала одну ожидающую заявку; новых ошибок callback в журнале за эту попытку нет. Секреты и данные профиля не выводились.
- Локальный dev web использует bind mount, запущен и ответил 200 на `/api/health`; пересборка локального образа для этого изменения не требовалась.

## Ограничение и следующий шаг

Следующий шаг: администратору открыть `/settings`, одобрить ожидающую заявку и попросить пользователя нажать «Проверить статус» на странице ожидания.
