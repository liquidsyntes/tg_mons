## Реализовано

- Карточка UserSavedPost имеет nullable publishedPostId и publicationLinkedAt; исходный postId сохранён как референс. Привязка разрешена только к активному «Моему каналу» и переводит карточку в published. Отвязка сохраняет статус/черновик/плановую дату.
- PostPerformanceCheckpoint хранит просмотры в окнах [24,26]/[48,50] часов с фактическим capturedAt. Уникальность postId/час, без перезаписи поздними значениями. Контрольные точки сохраняются после очистки PostSnapshot.
- При привязке подходящие исторические снимки поста и сопоставимых предшественников переносятся в долговременные точки. Пропущенная история не подменяется текущими просмотрами.
- Медиана: другие посты того же канала/contentType/isAd за предыдущие 30 дней, минимум 5 замеров отдельно для 24/48 ч. Нули учитываются, процент при нулевой медиане не вычисляется.
- Адресный сбор связанных публикаций включён в существующий часовой ad-reach проход через TaskCoordinator. До 500 кандидатов, пакеты до 100; основной collector также записывает точки. Сетевые ошибки не помечают пост удалённым.
- API выбора публикации с поиском/пагинацией и серверной проверкой доступа; UI привязки/смены/отвязки, фактической даты и результатов на доске. При смене «Моего канала» старая связь остаётся доступной при сохранённом доступе; после снятия доступа содержимое скрыто.

## Ограничения

- Визуальная браузерная проверка не выполнялась. Ожидание реальных 24/48 часов в Telegram не выполнялось; worker проверен моками и локальным запуском.
- Историю за пропущенное окно нельзя восстановить. При выключенном cron, сетевых ошибках или превышении лимита кандидатов точка может отсутствовать.
- Удаление адресный сбор подтверждает только явным MessageEmpty; отсутствие сообщения само по себе не считается удалением.
- При физическом удалении исходного референса действует прежний Cascade. Новая SetNull-связь защищает карточку от удаления отдельной целевой публикации.
