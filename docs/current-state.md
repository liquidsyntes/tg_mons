# Текущее состояние и передача работы

Снимок: 28 октября 2026 года. База исправления: `9b09c51`, ветка `main`; до правок рабочее дерево было чистым. На сервере этот коммит развёрнут, но исправление Telegram callback ниже ещё не развёрнуто. Перед следующей задачей проверить Git и сервер заново.

## Реализовано в исходниках

- Новый пользователь входит через Telegram OpenID Connect и получает статус `PENDING`. До одобрения администратора ему доступна только страница ожидания. `ACTIVE` получает доступ, `BLOCKED` не может войти снова и теряет доступ по действующей cookie.
- Администратор видит подтверждённый Telegram-профиль в `/settings` и может одобрить, удалить ожидающую заявку, заблокировать или вернуть аккаунт в заявки. Старые парольные аккаунты продолжают работать и могут привязать Telegram к своему профилю.
- Обычная регистрация по инвайту закрыта; сохранён первичный bootstrap администратора по мастер-ключу. Исторические `InviteCode` в БД не удалялись.
- Добавлены OIDC-маршруты, серверная проверка ID-токена, миграция статуса и Telegram-полей `User`, новая зависимость `openid-client`, настройки web и соответствующие тесты. Обновлены README, API, схема БД, эксплуатационная инструкция, архитектура и карта проекта.

- Локальные web, worker и PostgreSQL запущены; PostgreSQL healthy. `/api/health` ответил 200, `/login` ответил 200, заявки без сессии ответили 401, `/pending` без сессии перенаправил на вход. Telegram OIDC discovery ответил 200; конфигурация Client ID и Secret в локальном web доступна, значения не выводились.
- GitHub CI для `9b09c51` прошёл. На сервере read-only проверка подтвердила этот коммит, наличие переменных Telegram Login в web, применённую миграцию и заголовки Nginx с публичным доменом. Неподписанный запрос к callback действительно перенаправлялся на `https://localhost:4000`.
