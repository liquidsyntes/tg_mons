## Реализовано

- `AiOperation` и `AiProviderCall`, enum статуса, лимиты в SystemSetting; миграция `20261116043000_ai_operations` применена локально. Всего 27 моделей и 34 миграции.
- Все 10 AI-маршрутов и сканер используют серверное резервирование с Idempotency-Key и PostgreSQL advisory lock. Инициаторы user/system/master разделены. Повтор проверяет текущий доступ и не отправляет генерацию заново.
- Отдельный учёт каждой попытки chat/Decisions: модель, время, токены, подтверждённая стоимость USD или null, безопасный код ошибки. Лимиты проверяются до запроса, HTTP не выполняется внутри транзакции.
- UNKNOWN при истечении lease/неизвестном исходе, без автоматической повторной генерации. Ответ операции хранится 7 дней, затем очищается при следующем резервировании; метаданные остаются.
- Клиент объединяет двойные нажатия, сохраняет ключ после потери соединения и в sessionStorage, использует оригинальный ключ при присоединении к активной операции. После UNKNOWN новая генерация требует явного решения пользователя.
- ADMIN-раздел использования AI: фильтры периода/инициатора/типа, пагинация, расходы и неизвестная стоимость, токены, настройки лимитов. Миграция отключает пользовательские лимиты по умолчанию; глобальный параллелизм 4.
- Доступ к каналам/исходным отчётам проверяется перед replay; пользовательское сканирование выбирает только свои каналы. CLI экспериментов остаётся автономным и не входит в журнал приложения.
