# Git-процесс

Памятка согласована с [AGENTS.md](../AGENTS.md) и [GEMINI.md](../GEMINI.md). Работа выполняется в основном checkout `C:\TgMon` / `/mnt/c/TgMon`; отдельный worktree не используется.

## Перед работой

```bash
git status --short
git branch --show-current
git log -5 --oneline
git diff --stat main
```

Сначала учтите незакоммиченные изменения и текущую задачу. Не переключайте ветки, не перезаписывайте файлы и не повторяйте уже сделанную работу без проверки. Если задача продолжает текущую доработку, её изменения сохраняются в существующей ветке.

Работайте в текущей ветке основного checkout. Если задача требует изоляции или пользователь назвал новую ветку, используйте описательное имя с префиксом `codex/`:

```bash
git switch -c codex/describe-task
```

Команда создаёт ветку от текущего HEAD. Исходную ветку и необходимость обновления main определяют до её выполнения; автоматический pull в грязный checkout не является шагом подготовки.

## Коммит и публикация

После завершённой задачи с изменениями выполняйте обычный commit и push в соответствующий upstream: это разрешено текущими правилами проекта. PR, слияние и force push требуют отдельного поручения. Перед коммитом проверьте полный diff и добавляйте только конкретные файлы задачи, не весь checkout:

```bash
git diff --check
git diff
# git add <проверенные файлы задачи>
git diff --cached
```

Не добавляйте `.env`, сессии, ключи, дампы данных, node_modules и артефакты сборки. Одна логическая задача — один связный коммит; используйте Conventional Commits, например `docs(project): document Telegram article recovery`.

После push сравните локальный и удалённый коммиты выбранной ветки:

```bash
git rev-parse HEAD
git ls-remote origin refs/heads/codex/describe-task
```

Имена веток в примерах нужно заменить на фактические. Если upstream отсутствует, но remote и целевая ветка однозначны, задайте upstream при обычном push. Не выполняйте force push и не создавайте merge commit вручную. Успешный тест не является разрешением на merge или production-деплой.

## После доставки

Проверяйте статус checkout и не удаляйте ветку с незавершённой работой. Push не меняет работающие контейнеры: при изменении кода обновляйте затронутые локальные Docker-сервисы до коммита; при изменении только документации Docker не требуется. Порядок пересборки и проверок описан в [эксплуатации](deployment.md).
