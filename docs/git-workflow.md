## Перед работой

```bash
git status --short
git branch --show-current
git log -5 --oneline
git diff --stat main
```

Сначала учтите незакоммиченные изменения и текущую задачу. Не переключайте ветки, не перезаписывайте файлы и не повторяйте уже сделанную работу без проверки. Если задача продолжает текущую доработку, её изменения сохраняются в существующей ветке.

Для новой независимой задачи используйте описательную ветку; по умолчанию префикс `codex/`:

```bash
git switch -c codex/describe-task
```

Команда создаёт ветку от текущего HEAD. Исходную ветку и необходимость обновления main определяют до её выполнения; автоматический pull в грязный checkout не является шагом подготовки.

## Коммит и публикация

Коммит, push, открытие PR и слияние выполняются только по явному поручению пользователя. Перед коммитом проверьте полный diff и добавляйте только конкретные файлы задачи, не весь checkout:

```bash
git diff --check
git diff
# git add <проверенные файлы задачи>
git diff --cached
```

Не добавляйте `.env`, сессии, ключи, дампы данных, node_modules и артефакты сборки. Одна логическая задача — один связный коммит; используйте Conventional Commits, например `docs(project): document Telegram article recovery`.

После разрешённого push сравните локальный и удалённый коммиты выбранной ветки:

```bash
git rev-parse HEAD
git ls-remote origin refs/heads/codex/describe-task
```

Имена веток в примерах нужно заменить на фактические. Не выполняйте force push и не создавайте merge commit вручную. Способ слияния согласуется в рамках поручения; сам по себе успешный тест не является разрешением на merge или деплой.

## После доставки

Проверяйте статус checkout и не удаляйте ветку с незавершённой работой. Обновление Docker — отдельная операция: push не меняет работающие контейнеры. Порядок пересборки и проверок описан в [эксплуатации](deployment.md).
