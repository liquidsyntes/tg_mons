# О проекте TgMon (Telegram Monitor)

**TgMon** — платформа для мониторинга, сравнения и анализа Telegram-каналов и групп. Она собирает данные через MTProto, сохраняет историю и строит сводные метрики для таблиц и детальных страниц.

## Ключевые возможности

1. **Сбор и аналитика контента**
   - Сбор подписчиков, просмотров, реакций, комментариев и репостов через GramJS/MTProto.
   - ER, ERR, VR, средние просмотры и дельты подписчиков за 24ч, 7д и 30д.
   - Для групп в месте ERR показывается CR — среднее число комментариев на пост за семь дней относительно текущего числа участников. Это позволяет сравнивать активность групп, для которых Telegram не отдаёт просмотры.
   - Для каждого нового поста сохраняется число подписчиков на момент первой записи; оно используется в ER.

2. **Понятные пустые значения в таблицах**
   - Вместо прочерка для ER, ERR, VR, просмотров и Last Fact UI может показать «нет постов за 24ч», «не постил 7д», «реакции скрыты», «группа» или «сбор не выполнен».
   - Дельты подписчиков показывают фактическое покрытие периода, если оно заметно отличается от 24ч, 7д или 30д.

3. **Сравнение и скоринг**
   - Сравнение с «Моим каналом»: размер аудитории, рост и активность публикаций.
   - EP и Content Score используют собранные метрики для ранжирования и анализа контента.

## Технологический стек

- Next.js 15 (App Router), React 19 и TypeScript.
- PostgreSQL и Prisma.
- GramJS для MTProto-сбора, отдельный worker с `node-cron`.
- Tailwind CSS, Recharts, Vitest и Docker Compose.

## Поток данных

1. Worker собирает снапшоты аудитории и посты Telegram, затем материализует дневные показатели.
2. Metrics Engine строит сводку по дневным агрегатам либо по исходным данным, если агрегаты ещё отсутствуют.
3. В конце каждого цикла worker при заданных `WEB_INTERNAL_URL` и `COLLECT_API_TOKEN` вызывает внутренний endpoint веб-процесса, чтобы сбросить кэш метрик и рекомендаций лучшего времени публикации.
4. UI выводит значения, их покрытие и причины отсутствия данных.
