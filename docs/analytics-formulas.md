# Аналитические метрики и формулы

Этот документ описывает метрики сводной таблицы каналов. Расчёт выполняется двумя путями: по дневным агрегатам `ChannelMetricDaily` и по исходным постам и снапшотам, если агрегатов ещё нет. Для общих метрик оба пути используют `src/lib/metrics/aggregate.ts`; расчёт среднего охвата за 24 часа вынесен в `computeAvgViews24h` из `src/lib/metrics/calculate.ts`.

## ER (Engagement Rate)

- **Формула для одного поста:** `(views + reactions + comments + forwards) / subscribersAtPublish * 100`.
- **За период:** среднее арифметическое значений ER по постам, у которых `subscribersAtPublish > 0`.
- **Источник:** поля `views`, `reactions`, `comments`, `forwards` и `subscribersAtPublish` из `Post`; расчёт — `calculatePostER` и `aggregateChannelER` в `src/lib/metrics/engagement.ts`.
- **Когда `null`:** если за период нет ни одного поста с положительным `subscribersAtPublish`.
- **В UI:** `MetricCell` сначала показывает «сбор не выполнен» для статуса `error` или `stale`, затем «нет постов за 24ч» для ER 24ч без новых постов и «не постил 7д» без постов за семь дней. В остальных случаях пустой ER получает подпись «реакции скрыты»; она является общей подсказкой компонента для ER/ERR и не заменяет проверку `subscribersAtPublish` в расчёте.

`subscribersAtPublish` сохраняется только при создании поста. При последующих upsert-обновлениях поста это поле не передаётся в `update`, поэтому уже записанное значение не меняется вместе с очередным сбором. Для восстановления исторических значений используется `npx tsx scripts/repair-subscribers.ts`: скрипт ищет снапшот того же канала на момент публикации или раньше, а при его отсутствии — ближайший последующий снапшот.

## ERR (Engagement Rate by Reach)

- **Формула для одного поста:** `(reactions + comments + forwards) / views * 100`.
- **За период (`err24h`, `err7d`):** среднее арифметическое ERR по постам с `views > 0`.
- **Источник:** поля `views`, `reactions`, `comments` и `forwards` из `Post`; расчёт — `calculatePostERR` и `aggregateChannelERR` в `src/lib/metrics/engagement.ts`.
- **Когда `null`:** если нет постов с положительным числом просмотров либо если у всех таких постов сумма `reactions + comments + forwards` равна нулю. Второе условие служит эвристикой скрытой или недоступной вовлечённости.
- **В UI:** для каналов отображаются ERR 24ч и 7д с тем же порядком причин `MetricCell`: «сбор не выполнен», «нет постов за 24ч», «не постил 7д», затем «реакции скрыты». Для групп ERR не показывается: на его месте выводится CR.

## `trueErr7d` и отличие от `err7d`

Обе метрики используют одну базовую формулу ERR: `(reactions + comments + forwards) / views * 100`, но усредняются по-разному.

- **`err7d`:** среднее значений ERR отдельных постов за семь дней (`aggregateChannelERR`).
- **`trueErr7d` в materialized-пути:** дневная материализация сначала считает дневной ERR из суммарных вовлечений и просмотров за день. Затем `buildMetricsFromMaterialized` взвешивает ERR каждой строки `channel_metrics_daily` на число постов в ней: `sum(daily.err * daily.postsCount) / sum(daily.postsCount)`.
- **`trueErr7d` в fallback-пути:** считается напрямую по постам с `views !== null` в окне от 7 до 1 дня назад как отношение суммарной вовлечённости к суммарным просмотрам. Новые посты за последние 24 часа в этом расчёте не участвуют.

В materialized-пути `trueErr7d` равен `null`, если в периоде нет строк с постами; в fallback-пути — если среднее число просмотров по подходящим постам равно нулю. Это значение используется при расчёте Content Score.

## CR (Comments Rate, `cr7d`)

- **Формула:** `(сумма comments за 7 дней / число постов за 7 дней) / currentMembers * 100`.
- **Источник:** `comments` и `publishedAt` из `Post`, а также текущее число участников: последнее поле `followers` из `ChannelMetricDaily` в materialized-пути или последний `Snapshot` в fallback-пути. Расчёт есть в обеих функциях `src/lib/metrics/aggregate.ts`.
- **Когда `null`:** если нет постов за последние семь дней, `currentMembers` отсутствует или равен нулю.
- **В UI:** для `type === 'group'` CR 7д заменяет ERR в desktop- и mobile-списках, потому что для групп Telegram не отдаёт просмотры. Для CR в `MetricCell` не передаётся причина, поэтому при `null` выводится обычное «—».

## Средние просмотры и VR

### `avgViews24h`

- **Формула:** среднее `views` по постам, опубликованным в окне от 48 до 24 часов назад, с округлением до целого.
- **Откат:** если в этом окне нет постов с `views !== null`, берётся среднее по постам с просмотрами от 7 суток до 24 часов назад.
- **Источник:** `publishedAt` и `views` из `Post`; единая функция `computeAvgViews24h` вызывается и materialized-, и fallback-путём. Тест `src/lib/metrics/__tests__/aggregate.test.ts` проверяет одинаковый результат обоих путей.
- **Когда `null`:** если в основном окне и при откате нет постов с известными просмотрами.
- **В UI:** пустая ячейка получает одну из причин `MetricCell`: «сбор не выполнен», «нет постов за 24ч», «не постил 7д» или для группы «группа».

### VR (View Rate)

- **Формула:** `avgViews / currentMembers * 100`, результат округляется до двух знаков после запятой.
- **Источники:** `avgViews24h` использует описанное выше окно; для 7д и 30д используются средние просмотры соответствующего периода. `currentMembers` берётся из последней дневной агрегированной строки или последнего снапшота.
- **Когда `null`:** если `currentMembers` отсутствует или не больше нуля, либо соответствующее среднее просмотров равно `null`.
- **В UI:** `MetricCell` выводит «сбор не выполнен», «нет постов за 24ч», «не постил 7д» или «группа» по тому же порядку проверок, что и для `avgViews24h`.

## Дельты подписчиков

Для 24ч, 7д и 30д функции `calculateDelta` и `calculateDeltaFromData` возвращают три значения:

- **Абсолютная дельта:** `currentMembers - baselineMembers`.
- **Процентная дельта:** `(currentMembers - baselineMembers) / baselineMembers * 100`, округлённая до двух знаков.
- **Покрытие (`coverageDays`):** разница в днях между текущим временем и временем baseline, округлённая до ближайшего целого.

`baseline` — строка дневных агрегатов или снапшот на границе периода; при отсутствии записи на границе функции используют доступную запись из переданных данных. Дельта возвращает `null` для абсолютного значения, процента и покрытия, если отсутствуют текущие подписчики или baseline, либо число подписчиков в baseline равно нулю.

Дельты отображает не `MetricCell`, а `DeltaBadge`: при `null` он показывает «н/д». В таблицах ему передаются номинальные периоды 1, 7 и 30 дней. Если фактическое покрытие отличается от номинального более чем на один день, рядом с дельтой выводится суффикс `(Nд)` с подсказкой `данные за N дней из M`.

## Антифрод и Индекс цитирования (Anti-Fraud & Citation Index)

Для выявления аномалий, неорганической активности и возможных накруток платформа TgMon использует многофакторный анализ (`src/lib/fraudDetector.ts` и `src/lib/citationIndex.ts`). Анализ защищает от накрутки ботов, накрутки просмотров автопросмотрщиками и шаблонных накруток реакций бот-фермами.

Проверки выполняются на двух взаимосвязанных уровнях:
1. **Фоновый сборщик (`src/worker/collector.ts`):** в регулярном цикле сбора анализирует историю канала и при срабатывании эвристик сохраняет записи в таблицу базы данных `fraud_signals` (модель `FraudSignal`).
2. **Динамический аудит (`src/lib/metrics/queries.ts` -> `runFraudAudit`):** при отображении карточек и детальных отчётов объединяет сохранённые сигналы с актуальными метриками постов и рассчитывает единый нормализованный показатель риска `fraudScore` (0–100%).

---

### 1. Аномальная гладкость роста (`checkGrowthSmoothness`)

Выявляет неестественно равномерный, линейный прирост аудитории, характерный для бот-сервисов с фиксированным суточным лимитом подписок по расписанию.

- **Математическая формула:**
  Для упорядоченной по времени выборки из $N$ ежедневных замеров числа подписчиков $F_0, F_1, \dots, F_{N-1}$ вычисляются суточные дельты:
  $$\Delta_i = F_i - F_{i-1}, \quad i = 1, \dots, N-1$$
  Средний суточный прирост ($\mu_\Delta$) и выборочное стандартное отклонение ($\sigma_\Delta$):
  $$\mu_\Delta = \frac{1}{N-1} \sum_{i=1}^{N-1} \Delta_i, \quad \sigma_\Delta = \sqrt{\frac{1}{N-1} \sum_{i=1}^{N-1} (\Delta_i - \mu_\Delta)^2}$$
  Коэффициент вариации (Coefficient of Variation, $CV$):
  $$CV = \frac{\sigma_\Delta}{\mu_\Delta}$$
- **Условия срабатывания:**
  - Наличие истории метрик не менее 14 дней ($N \ge 14$). При $N < 14$ проверка возвращает `flag: false` («Недостаточно данных для анализа (менее 14 дней)»).
  - Положительный средний суточный прирост ($\mu_\Delta > 0$). При $\mu_\Delta \le 0$ проверка возвращает `flag: false` («Нет монотонного роста (средний прирост <= 0)»).
  - **Порог аномалии:** $CV < 0.1$ (относительное стандартное отклонение приростов составляет менее 10% от среднего).
- **Результат:** `GrowthSmoothnessResult { flag: boolean, cv: number, reason: string }`.
- **Смысл и интерпретация:** Естественный органический рост всегда подвержен волатильности: выходу вирального контента, выходным дням, естественным отпискам и внешним рекламным кампаниям. Значение $CV < 0.1$ на отрезке от двух недель свидетельствует о систематическом добавлении подписчиков скриптом с искусственным суточным лимитом.

### 2. Аномальное соотношение просмотров к подписчикам (`checkViewsToSubsRatio`)

Выявляет каналы с балластной («мёртвой») бот-аудиторией либо с искусственной накруткой просмотров на публикации.

- **Математическая формула:**
  Отношение среднего числа просмотров последних $K$ публикаций с известными просмотрами к текущему числу подписчиков канала ($S_{\text{current}}$):
  $$\text{Ratio} = \frac{\bar{V}}{S_{\text{current}}} = \frac{\frac{1}{K}\sum_{j=1}^{K} V_j}{S_{\text{current}}}$$
  где $V_j$ — просмотры $j$-й публикации, $S_{\text{current}}$ — текущее число участников (`currentMembers`).
- **Условия срабатывания:**
  - Наличие $S_{\text{current}} > 0$. При $S_{\text{current}} \le 0$ возвращается `flag: false`.
  - В выборке из 20–30 последних постов должно присутствовать не менее 5 постов с известными просмотрами ($K \ge 5$). При $K < 5$ возвращается `flag: false`.
  - **Аномально низкие просмотры:** $\text{Ratio} < 0.05$ (менее 5% от числа подписчиков) $\rightarrow$ подозрение на накрутку подписчиков («мёртвые» боты).
  - **Аномально высокие просмотры:** $\text{Ratio} > 1.50$ (более 150% от числа подписчиков) $\rightarrow$ подозрение на искусственную накрутку просмотров автопросмотрщиками.
- **Результат:** `FraudSignalResult { flag: boolean, ratio: number, reason: string }`.
- **Смысл и интерпретация:** Для живых каналов в Telegram охват поста обычно составляет от 10% до 50% аудитории. Доля просмотров ниже 5% указывает на бот-балласт, а стабильное превышение 150% без вирального внешнего цитирования — на закупку автопросмотров.

### 3. Нескоррелированные скачки подписчиков (`checkUncorrelatedSpikes`)

Выявляет резкие единовременные наплывы подписчиков, которые произошли в дни без публикаций постов на канале и без внешних упоминаний канала.

- **Математическая формула динамического порога:**
  Для каждого дня вычисляется дневной прирост $\Delta_i = F_i - F_{i-1}$. Для всех положительных приростов определяется динамический адаптивный порог всплеска $T$:
  $$T = \max\Big(3 \cdot \mu_\Delta, \, 50, \, 0.005 \cdot F_{\max}\Big)$$
  где:
  - $3 \cdot \mu_\Delta$ — превышение среднего дневного прироста более чем в 3 раза;
  - $50$ — абсолютный нижний порог, исключающий шум на микроканалах;
  - $0.005 \cdot F_{\max}$ — относительный порог 0.5% от максимального зафиксированного числа подписчиков, защищающий крупные каналы от ложных срабатываний при естественных флуктуациях.
  
  День $D$ классифицируется как день потенциального всплеска, если $\Delta_D > T$.

- **Временное окно корреляции событий:**
  Для каждого дня всплеска $D$ проверяется наличие активности в двухдневном окне $[D - 1, D]$:
  $$\text{hasEvent}(D) = \exists e \in (\text{postsDates} \cup \text{mentionsDates}) : \text{date}(e) \in \{D, D - 1\}$$
  - Наличие собственных публикаций на канале (`postsDates`).
  - Наличие входящих упоминаний/репостов из других каналов (`mentionsDates`).
  
  Если в двухдневном окне не зафиксировано ни одного поста и ни одного упоминания ($!\text{hasPost} \land !\text{hasMention}$), всплеск признаётся **необъяснимым (аномальным)**.

- **Условия срабатывания:**
  - Наличие $\ge 2$ точек истории метрик и хотя бы одного положительного прироста.
  - Обнаружение хотя бы одного необъяснимого скачка ($\text{spikesCount} \ge 1$).
- **Результат:** `UncorrelatedSpikesResult { flag: boolean, spikesCount: number, dates: string[], reason: string }`.
- **Смысл и интерпретация:** Всплеск аудитории без контента и без внешнего трафика практически всегда вызван закупкой мотивированного трафика или ботов.

### 4. Индекс цитирования (`calculateCitationIndex`) и быстрый рост без цитирования (`checkLowCitationGrowth`)

Оценивает внешний органический вес канала на основе упоминаний и репостов, взвешенных по размеру аудитории цитирующих каналов.

- **Математическая формула Индекса цитирования (Citation Index, CI):**
  $$\text{CI} = \sum_{i=1}^{M} \Big(\text{count}_i \times \log_{10}(\text{subscribers}_i)\Big)$$
  где:
  - $M$ — количество внешних каналов, упоминавших целевой канал за последние 30 дней.
  - $\text{count}_i$ — число упоминаний/репостов со стороны $i$-го канала.
  - $\text{subscribers}_i$ — число подписчиков цитирующего канала $i$ (`citing_subscribers`).
- **Граничные условия и нормализация:**
  - **Кластеризация весов:** если $\text{subscribers}_i \le 1$, вес приравнивается к 0 (предотвращает $\log_{10}(1) = 0$, $\log_{10}(0) = -\infty$ и отрицательные веса).
  - **Временное окно:** учитываются только упоминания за последние 30 дней ($0 \le t_{\text{now}} - t_{\text{mention}} \le 30\text{ дней}$, с допуском 24 ч на расхождение часов серверов).
  - **Исключение самоцитирований:** упоминания, где ID источника совпадает с ID целевого канала (`sourceChannelId === targetId`), исключаются.
  - **Округление:** итоговое значение $\text{CI}$ округляется до 2 знаков после запятой; при отсутствии упоминаний возвращается 0.
- **Математическая формула проверки быстрого роста (`checkLowCitationGrowth`):**
  Вычисляется 30-дневный прирост подписчиков в процентах:
  $$G_{30\text{d}} = \frac{F_{\text{now}} - F_{30\text{d}}}{F_{30\text{d}}} \times 100\%$$
  - **Условие срабатывания:**
    $$G_{30\text{d}} > 5\% \quad \text{и} \quad \text{CI} \le 1.0$$
- **Результат:** `LowCitationGrowthResult { flag: boolean, citationIndex: number, growthRate: number, growthPercent: number, value: number, reason: string }`.
- **Смысл и интерпретация:** Логарифмический масштаб точно отражает авторитет источника: одно упоминание от канала на 1 000 подписчиков даёт $\log_{10}(1000) = 3$ балла, на 10 000 — 4 балла, на 100 000 — 5 баллов. Если канал прирастает более чем на 5% в месяц, но имеет $\text{CI} \le 1$ (менее 1 упоминания от канала с 10 подписчиками), трафик генерируется вне экосистемы открытого Telegram (каталоги накруток, боты).
- **В UI:** Значение $\text{CI}$ отображается в карточке канала `MyChannelCard` в блоке «Индекс цит. (30д)». При срабатывании флага ячейка подсвечивается предупреждающим стилем с иконкой `AlertTriangle`.

### 5. Однородность реакций (`checkUniformReactionRatio`)

Выявляет автоматизированную накрутку реакций и шаблонного вовлечения на публикации через бот-фермы.

- **Математическая формула:**
  Для каждого поста выборки вычисляется индивидуальный Engagement Rate by Reach ($\text{ERR}_k$):
  $$\text{ERR}_k = \frac{R_k + C_k + F_k}{V_k} \times 100\%$$
  где $R_k$ — реакции, $C_k$ — комментарии, $F_k$ — пересылки (forwards), $V_k$ — просмотры $k$-го поста.
  
  Анализируется скользящее окно до 20 последних публикаций, отсортированных по убыванию даты ($N \le 20$).
  
  Вычисляются средний ERR ($\mu_{\text{ERR}}$) и выборочное стандартное отклонение совокупности ($\sigma_{\text{ERR}}$):
  $$\mu_{\text{ERR}} = \frac{1}{N} \sum_{k=1}^{N} \text{ERR}_k$$
  $$\sigma_{\text{ERR}} = \sqrt{\frac{1}{N} \sum_{k=1}^{N} (\text{ERR}_k - \mu_{\text{ERR}})^2}$$
  Коэффициент вариации реакций (Coefficient of Variation, $CV$):
  $$CV = \frac{\sigma_{\text{ERR}}}{\mu_{\text{ERR}}}$$
- **Условия срабатывания:**
  - Выборка должна содержать не менее 10 постов с ненулевыми просмотрами ($N \ge 10$). При $N < 10$ проверка возвращает `flag: false` («Недостаточно данных для анализа (менее 10 постов)»).
  - Положительный средний ERR ($\mu_{\text{ERR}} > 0$). При $\mu_{\text{ERR}} \le 0$ возвращается `flag: false`.
  - **Порог шаблонности:** $CV < 0.1$ (относительное отклонение ERR между публикациями составляет менее 10%).
- **Результат:** `UniformReactionRatioResult { flag: boolean, cv: number, reason: string, avgErr?: number, postsCount?: number, signal?: FraudSignal }`.
- **Смысл и интерпретация:** Живые пользователи реагируют на контент крайне неравномерно в зависимости от темы поста, времени публикации и эмоционального окраса. Разброс вовлеченности в реальных каналах превышает 20–50% ($CV \ge 0.2$). Коэффициент вариации $CV < 0.1$ однозначно указывает на закупку шаблонных пакетов реакций с фиксированным процентом от просмотров.

### 6. Единый показатель риска (`fraudScore`) и аудит (`runFraudAudit`)

Функция `runFraudAudit(channel)` консолидирует результаты четырёх ключевых векторов проверки:
1. `viewsToSubsRatio` (Аномальное соотношение просмотров к подписчикам)
2. `growthSmoothness` (Аномальная гладкость роста)
3. `uncorrelatedSpikes` (Нескоррелированные скачки подписчиков)
4. `uniformReactionRatio` (Равномерность реакций ERR)

- **Математическая формула агрегации:**
  Каждая сработавшая проверка добавляет ровно 25 пунктов к итоговому скору риска:
  $$\text{fraudScore} = \sum_{j=1}^{4} \Big(\text{flag}_j \times 25\Big) \in \{0, 25, 50, 75, 100\}$$
  где $\text{flag}_j \in \{0, 1\}$.

- **Градации риска и визуализация в UI (`RiskBadge`):**
  - **0% — Clean (Низкий риск):** цвет `emerald` (`bg-emerald-500/15 text-emerald-400 border-emerald-500/30`), иконка `ShieldCheck`. Все проверки пройдены, сигналов накрутки не зафиксировано (подсказка: «Низкий риск накрутки»).
  - **25% — Low (Умеренный риск):** цвет `amber` (`bg-amber-500/15 text-amber-400 border-amber-500/30`), иконка `AlertTriangle`. Обнаружена одна изолированная аномалия.
  - **50% — Moderate (Повышенный риск):** цвет `rose` (`bg-rose-500/15 text-rose-400 border-rose-500/30`), иконка `AlertTriangle`. Два одновременных сигнала накрутки.
  - **75% — High (Высокий риск):** цвет `rose` (`bg-rose-500/15 text-rose-400 border-rose-500/30`), иконка `AlertTriangle`. Три сработавших фактора накрутки.
  - **100% — Critical (Критический риск):** цвет `rose` (`bg-rose-500/15 text-rose-400 border-rose-500/30`), иконка `AlertTriangle`. Все четыре детектора зафиксировали аномалии.
  - **Интерактивная подсказка (Tooltip):** при наведении на бейдж раскрывается подробный перечень всех сработавших факторов (например: `• Аномально гладкий рост (CV < 0.1): подозрение на накрутку`).


## Причины пустых ячеек в таблице

`getMetricReason` в `src/components/channel/cells/MetricCell.tsx` выбирает подпись в таком порядке:

1. `error` или `stale` — «сбор не выполнен»;
2. для метрики 24ч и `posts24h === 0` — «нет постов за 24ч»;
3. при `posts7d === 0` — «не постил 7д»;
4. для просмотров, VR и Last Fact у группы — «группа»;
5. для ER и ERR — «реакции скрыты».

Если для метрики причина не передана, `MetricCell` оставляет «—». Эти подписи объясняют отображение, а условия, при которых расчёт возвращает `null`, перечислены в разделах метрик выше.
