# Аналитические метрики и формулы

Этот документ описывает метрики сводной таблицы каналов. Расчёт выполняется двумя путями: по дневным агрегатам `ChannelMetricDaily` и по исходным постам и снапшотам, если агрегатов ещё нет. Для общих метрик оба пути используют `src/lib/metrics/aggregate.ts`; расчёт среднего охвата за 24 часа вынесен в `computeAvgViews24h` из `src/lib/metrics/calculate.ts`.

## ER (Engagement Rate)

- **Формула для одного поста:** `(views + reactions + comments + forwards) / subscribersAtPublish * 100`.
- **За период:** среднее арифметическое значений ER по постам, у которых `subscribersAtPublish > 0`.
- **Источник:** поля `views`, `reactions`, `comments`, `forwards` и `subscribersAtPublish` из `Post`; расчёт — `calculatePostER` и `aggregateChannelER` в `src/lib/metrics/engagement.ts`.
- **Когда `null`:** если за период нет ни одного поста с положительным `subscribersAtPublish`.
- **В UI:** `MetricCell` сначала показывает «сбор не выполнен» для статуса `error` или `stale`, затем «нет постов за 24ч» для ER 24ч без новых постов и «не постил 7д» без постов за семь дней. В остальных случаях пустой ER получает подпись «реакции скрыты»; она является общей подсказкой компонента для ER/ERR и не заменяет проверку `subscribersAtPublish` в расчёте.

`subscribersAtPublish` сохраняется только при создании поста. При последующих upsert-обновлениях поста это поле не передаётся в `update`, поэтому уже записанное значение не меняется вместе с очередным сбором. Для восстановления исторических значений используется `npx tsx scripts/repair-subscribers.ts`: скрипт ищет снапшот того же канала на момент публикации или раньше, а при его отсутствии — ближайший последующий снапшот.

## ERR (Engagement Rate by Reach)

- **Формула для одного поста:** `(reactions + comments + forwards) / views * 100`.
- **За период (`err24h`, `err7d`):** среднее арифметическое ERR по постам с `views > 0`.
- **Источник:** поля `views`, `reactions`, `comments` и `forwards` из `Post`; расчёт — `calculatePostERR` и `aggregateChannelERR` в `src/lib/metrics/engagement.ts`.
- **Когда `null`:** если нет постов с положительным числом просмотров либо если у всех таких постов сумма `reactions + comments + forwards` равна нулю. Второе условие служит эвристикой скрытой или недоступной вовлечённости.
- **В UI:** для каналов отображаются ERR 24ч и 7д с тем же порядком причин `MetricCell`: «сбор не выполнен», «нет постов за 24ч», «не постил 7д», затем «реакции скрыты». Для групп ERR не показывается: на его месте выводится CR.

## `trueErr7d` и отличие от `err7d`

Обе метрики используют одну базовую формулу ERR: `(reactions + comments + forwards) / views * 100`, но усредняются по-разному.

- **`err7d`:** среднее значений ERR отдельных постов за семь дней (`aggregateChannelERR`).
- **`trueErr7d` в materialized-пути:** дневная материализация сначала считает дневной ERR из суммарных вовлечений и просмотров за день. Затем `buildMetricsFromMaterialized` взвешивает ERR каждой строки `channel_metrics_daily` на число постов в ней: `sum(daily.err * daily.postsCount) / sum(daily.postsCount)`.
- **`trueErr7d` в fallback-пути:** считается напрямую по постам с `views !== null` в окне от 7 до 1 дня назад как отношение суммарной вовлечённости к суммарным просмотрам. Новые посты за последние 24 часа в этом расчёте не участвуют.

В materialized-пути `trueErr7d` равен `null`, если в периоде нет строк с постами; в fallback-пути — если среднее число просмотров по подходящим постам равно нулю. Это значение используется при расчёте Content Score.

## CR (Comments Rate, `cr7d`)

- **Формула:** `(сумма comments за 7 дней / число постов за 7 дней) / currentMembers * 100`.
- **Источник:** `comments` и `publishedAt` из `Post`, а также текущее число участников: последнее поле `followers` из `ChannelMetricDaily` в materialized-пути или последний `Snapshot` в fallback-пути. Расчёт есть в обеих функциях `src/lib/metrics/aggregate.ts`.
- **Когда `null`:** если нет постов за последние семь дней, `currentMembers` отсутствует или равен нулю.
- **В UI:** для `type === 'group'` CR 7д заменяет ERR в desktop- и mobile-списках, потому что для групп Telegram не отдаёт просмотры. Для CR в `MetricCell` не передаётся причина, поэтому при `null` выводится обычное «—».

## Средние просмотры и VR

### `avgViews24h`

- **Формула:** среднее `views` по постам, опубликованным в окне от 48 до 24 часов назад, с округлением до целого.
- **Откат:** если в этом окне нет постов с `views !== null`, берётся среднее по постам с просмотрами от 7 суток до 24 часов назад.
- **Источник:** `publishedAt` и `views` из `Post`; единая функция `computeAvgViews24h` вызывается и materialized-, и fallback-путём. Тест `src/lib/metrics/__tests__/aggregate.test.ts` проверяет одинаковый результат обоих путей.
- **Когда `null`:** если в основном окне и при откате нет постов с известными просмотрами.
- **В UI:** пустая ячейка получает одну из причин `MetricCell`: «сбор не выполнен», «нет постов за 24ч», «не постил 7д» или для группы «группа».

### VR (View Rate)

- **Формула:** `avgViews / currentMembers * 100`, результат округляется до двух знаков после запятой.
- **Источники:** `avgViews24h` использует описанное выше окно; для 7д и 30д используются средние просмотры соответствующего периода. `currentMembers` берётся из последней дневной агрегированной строки или последнего снапшота.
- **Когда `null`:** если `currentMembers` отсутствует или не больше нуля, либо соответствующее среднее просмотров равно `null`.
- **В UI:** `MetricCell` выводит «сбор не выполнен», «нет постов за 24ч», «не постил 7д» или «группа» по тому же порядку проверок, что и для `avgViews24h`.

## Дельты подписчиков

Для 24ч, 7д и 30д функции `calculateDelta` и `calculateDeltaFromData` возвращают три значения:

- **Абсолютная дельта:** `currentMembers - baselineMembers`.
- **Процентная дельта:** `(currentMembers - baselineMembers) / baselineMembers * 100`, округлённая до двух знаков.
- **Покрытие (`coverageDays`):** разница в днях между текущим временем и временем baseline, округлённая до ближайшего целого.

`baseline` — строка дневных агрегатов или снапшот на границе периода; при отсутствии записи на границе функции используют доступную запись из переданных данных. Дельта возвращает `null` для абсолютного значения, процента и покрытия, если отсутствуют текущие подписчики или baseline, либо число подписчиков в baseline равно нулю.

Дельты отображает не `MetricCell`, а `DeltaBadge`: при `null` он показывает «н/д». В таблицах ему передаются номинальные периоды 1, 7 и 30 дней. Если фактическое покрытие отличается от номинального более чем на один день, рядом с дельтой выводится суффикс `(Nд)` с подсказкой `данные за N дней из M`.

## Антифрод (Fraud Detection)

Для выявления аномалий и возможных накруток (`src/lib/fraudDetector.ts`) используются две эвристики, результаты которых сохраняются в таблицу `fraud_signals`. Эти проверки выполняются в процессе работы воркера (`src/worker/collector.ts`).

### Аномальная гладкость роста (`checkGrowthSmoothness`)
- **Формула:** Коэффициент вариации (CV) ежедневных приростов подписчиков: `CV = StdDev(deltas) / Avg(deltas)`.
- **Условие срабатывания:** Если `CV < 0.1` (отклонения составляют менее 10% от среднего прироста) при наличии истории не менее 14 дней и положительном среднем приросте.
- **Смысл:** Естественный рост аудитории обычно сопровождается колебаниями (виральный контент, отписки, рекламные кампании). Идеально ровный прирост с околонулевой дисперсией указывает на вероятную накрутку ботами по расписанию.

### Аномальное соотношение просмотров (`checkViewsToSubsRatio`)
- **Формула:** Отношение среднего числа просмотров последних постов (до 20-30 штук) к текущему числу подписчиков: `avgViews / currentMembers`.
- **Условия срабатывания:** При наличии не менее 5 постов с просмотрами:
  - `ratio < 0.05` (менее 5%) — аномально мало просмотров, вероятна накрутка «мертвых» ботов в подписчики.
  - `ratio > 1.5` (более 150%) — аномально много просмотров, вероятна накрутка просмотров на посты.
- **Смысл:** Позволяет находить дисбаланс между аудиторией и ее активностью.

## Причины пустых ячеек в таблице

`getMetricReason` в `src/components/channel/cells/MetricCell.tsx` выбирает подпись в таком порядке:

1. `error` или `stale` — «сбор не выполнен»;
2. для метрики 24ч и `posts24h === 0` — «нет постов за 24ч»;
3. при `posts7d === 0` — «не постил 7д»;
4. для просмотров, VR и Last Fact у группы — «группа»;
5. для ER и ERR — «реакции скрыты».

Если для метрики причина не передана, `MetricCell` оставляет «—». Эти подписи объясняют отображение, а условия, при которых расчёт возвращает `null`, перечислены в разделах метрик выше.
