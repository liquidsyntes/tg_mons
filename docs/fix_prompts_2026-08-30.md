## Промпт 1. `.gitattributes` + нормализация переводов строк (КРИТИЧНО, делай первым)

**Проблема:** 77 файлов в `git status` «изменены», но `git diff --ignore-cr-at-eol --stat` пуст — все изменения только CRLF↔LF. В репо нет `.gitattributes`, кто-то пересохранил файлы под Windows. Это отравляет diff и review.

**Промпт:**

---

В проекте `/mnt/c/TgMon` (Next.js + TypeScript) в git status висит 77 изменённых файлов, но реальный контент не менялся — только переводы строк CRLF↔LF. В репо нет `.gitattributes`.

Задача: ввести нормализацию переводов строк и привести рабочее дерево в чистое состояние.

1. Создай `.gitattributes` в корне репо с содержимым:

```
# Нормализация переводов строк: в репо всегда LF
* text=auto eol=lf

# Bash-скрипты — строго LF
*.sh text eol=lf

# Windows-специфичное — можно CRLF
*.ps1 text eol=crlf
*.bat text eol=crlf

# Бинарники не трогать
*.png binary
*.jpg binary
*.db binary
```

2. Выполни `git add --renormalize .` — это применит LF ко всем текстовым файлам в индексе.

3. Покажи `git status --short` и `git diff --cached --stat | tail -5`. Ожидание: все ранее «изменённые» файлы либо исчезли из status, либо попали в staged с пустым содержательным diff.

4. Проверь, что содержательный diff пуст: `git diff --cached --ignore-cr-at-eol --stat` должен быть пустым.

5. НЕ делай коммит — покажи итог и остановись. Коммитом займётся человек.

Важно: если `git add --renormalize .` зацепит файлы с реальными изменениями контента (не только переводы строк) — остановись и покажи список таких файлов, не включая их в staged.

## Промпт 2. Починить mojibake в Telegram-алертах (КРИТИЧНО)

**Проблема:** `src/worker/collector.ts`, функция `sendTelegramAlert` — строки уведомлений содержат double-encoded mojibake: «РђРЅРѕРјР°Р»РёСЏ» вместо «Аномалия», «рџљЂ» вместо эмодзи 🚀. Алерты в Telegram приходят с битым текстом.

**Промпт:**

---

В проекте `/mnt/c/TgMon` почини mojibake в файле `src/worker/collector.ts`, функция `sendTelegramAlert`.

Сейчас в исходнике строки вида:
- «РђРЅРѕРјР°Р»РёСЏ РІ РєР°РЅР°Р»Рµ» (должно быть: «Аномалия в канале»)
- «РР·РјРµРЅРµРЅРёРµ: … РїРѕРґРїРёСЃС‡РёРєРѕРІ» (должно быть: «Изменение: … подписчиков»)
- «РўРµРєСѓС‰Р°СЏ Р°СѓРґРёС‚РѕСЂРёСЏ» (должно быть: «Текущая аудитория»)
- «рџљЂ» / «рџ”»» (должно быть: 🚀 / 📉)

Это double-encoding: оригинальный UTF-8 был прочитан как Windows-1251 и сохранён обратно в UTF-8.

Алгоритм:
1. Прочитай сырые байты файла (UTF-8).
2. Прогони весь файл через восстановление: encode строки как Windows-1251 → decode как UTF-8. Если результат содержит читаемую кириллицу и валиден — используй восстановленный текст. Если в файле есть фрагменты, которые НЕ проходят обратное декодирование (необратимые потери) — восстанови их вручную по смыслу.
3. Запиши файл в UTF-8 без BOM, переводы строк LF.
4. Убедись, что изменён только текст строк внутри `sendTelegramAlert` (и любых других mojibake-строк), логика не тронута.

Проверка после фикса:
- `grep -c 'рџ\|Рђ\|РЅРµ' src/worker/collector.ts` → 0
- `npx tsc --noEmit` → 0 ошибок
- `npm test` → все зелёные (collector.test.ts затрагивает этот файл)
- Покажи первые 3 строки функции `sendTelegramAlert` до и после.
