# Codebase Guide (Карта проекта)

Этот документ представляет собой навигатор по кодовой базе проекта TgMon для разработчиков. Проект использует монорепозиторный подход на базе Next.js.

## Структура директорий

```text
tg-monitor/
├── docker-compose.yml       # Конфигурация сервисов (web, worker, db)
├── prisma/                  # Схема базы данных (schema.prisma) и миграции
├── scripts/                 # Одноразовые утилиты обслуживания и диагностики БД
├── src/
│   ├── app/                 # Next.js App Router (UI и API Route Handlers)
│   ├── components/          # React-компоненты (UI kit, графики, секции)
│   ├── lib/                 # Бизнес-логика, утилиты, расчеты
│   └── worker/              # Фоновый процесс (MTProto Collector)
└── docs/                    # Документация проекта
```

---

## 1. Слой отображения и API (`src/app/`)

Проект построен на Next.js App Router.
- **Страницы (`page.tsx`)**: Отвечают за сборку макета и рендер компонентов.
  - `src/app/page.tsx` — Главный дашборд.
  - `src/app/settings/page.tsx` — Настройки системы (ИИ, провайдеры).
- **API Роуты (`route.ts`)**: Находятся в `src/app/api/`. Выступают связующим звеном между Frontend и Backend (вызывают функции из `src/lib/`). Например, `/api/settings` или `/api/stats/demographics`.

---

## 2. Слой бизнес-логики (`src/lib/`)

Здесь находится ядро аналитики TgMon. Все функции в этой папке можно использовать как из API, так и в серверных компонентах Next.js.

### Ключевые модули:
- **`ep.ts`**: Содержит алгоритм **EP (Effective Point)** и **CEI (Channel Expansion Index)**. Это сердце рейтинговой системы, использующее Z-score нормализацию и логарифмический Confidence Penalty.
- **`scoring.ts`**: Оценка контента (Content Score) и выдача буквенных грейдов (A+, B, C) на основе вовлеченности, рекламы и частоты.
- **`metrics.ts`**: Глубокий файл с агрегацией и экспортами.
- **`metrics/`**: Разделенная логика метрик: `queries.ts` (выборки), `aggregate.ts` (построение сводки), `engagement.ts` (расчет ER и ERR), `calculate.ts` (дельты, VR и `computeAvgViews24h`).
- **`materialize.ts`**: Логика материализации сырых данных в агрегированные таблицы (например, `ChannelMetricDaily`).
- **`fraudDetector.ts`**: Алгоритмы антифрода для выявления накруток (`checkGrowthSmoothness`, `checkViewsToSubsRatio`).
- **`openrouter.ts` & `ai-reports.ts`**: Обертки для вызова LLM (OpenRouter) и формирования отчетов.
- **`prisma.ts`**: Инициализация Prisma Client.
- **`cache.ts`**: In-memory кэширование для ускорения API ответов.

### Компоненты метрик
- **`src/components/channel/cells/MetricCell.tsx`**: Выводит значение метрики или её причину отсутствия; `getMetricReason` выбирает подпись для статуса сбора, отсутствия постов, групп и скрытой вовлечённости.

### Интерфейс мониторинга

- Заголовки сравнительной таблицы остаются английскими (Subscribers, Avg Views,
  ER, ERR, VR, CI). При горизонтальной прокрутке колонка Channel закреплена;
  сортировка доступна кнопками с клавиатуры. Боковые отступы уменьшены,
  фиксированный минимум ширины таблицы убран. Столбца Act. нет: отключение
  мониторинга и удаление доступны на странице канала.
- Отсутствие публикаций отображается кружками диаметром 8 px: голубой — за
  24 часа, розовый — за 7 дней. Период указан в подсказке при наведении и
  доступном имени индикатора. Нулевое значение метрики остаётся нулём.
- В «Моём канале» и избранном ERR берётся из `err24h`/`err7d`; у групп вместо
  ERR выводится CR за семь дней.
- Общая KPI-карточка ERR усредняет известные `err7d` каналов, исключая группы
  и нечисловые значения; без данных показывает `н/д`. API дашборда также
  возвращает рассчитанный `avgScore` для карточки Content Score.
- «Лучшее время для поста» показывает VR из `heatmap[].avgVr`: API уже возвращает
  проценты, дополнительное умножение на 100 не требуется. Это показатель охвата
  относительно аудитории, а не ERR. Отсутствие данных и ошибка загрузки имеют
  отдельные текстовые состояния.
- Только «Радар трендов» свёрнут по умолчанию. Кнопка в заголовке раскрывает
  сохранённый отчёт без генерации; «Обновить радар» запускает новый анализ.
  Ошибки обновления видны и в свёрнутом состоянии. Порядок остальных блоков
  главной страницы сохранён.

## 3. Фоновый сборщик - Worker (`src/worker/`)

Отдельный от Next.js процесс, который запускается через `npx tsx src/worker/index.ts` и работает в фоне 24/7.

### Ключевые модули:
- **`index.ts`**: Точка входа воркера. Содержит настройку `node-cron` для регулярного запуска обходов (постов и демографии).
- **`collector.ts`**: Главный цикл обхода (`runCollectCycle`).
  - Проходит по всем `isActive: true` каналам.
  - Собирает снапшоты (participants_count) и посты.
  - Обрабатывает таймауты и Rate Limits (`FLOOD_WAIT`) Telegram с экспоненциальной задержкой.
  - При получении `TelegramTimeoutError` пытается принудительно переподключить (`reconnect`) клиент для восстановления "мертвого" сокета и продолжения цикла.
  - Ведет счетчик `consecutiveErrors` (подряд идущих ошибок) для каждого канала. Отключает каналы при `consecutiveErrors` > 10, защищая общую очередь от зависаний.
- **`demographics.ts`**: Цикл еженедельного сбора языковой и гео-разбивки (`languages_graph`) через MTProto метод `stats.getBroadcastStats`.
- **`client.ts`**: Инициализация `TelegramClient` из библиотеки GramJS с использованием сессии из `.env`.
- **`auth.ts`**: CLI-скрипт для первоначальной генерации строки `TG_SESSION`.

---

## 4. Служебные скрипты (`scripts/`)

- **`repair-subscribers.ts`**: Восстанавливает `subscribersAtPublish` постов по снапшотам аудитории, предпочитая снапшот на момент публикации или раньше.
- **`audit-metrics.ts`**: Только читает БД и выводит диагностику пустых метрик по каналам и состоянию последних циклов сбора.

---

## Принципы работы

1. **Разделение вычислений и сбора**: Воркер **только** собирает и складывает сырые данные (Посты, Снапшоты) в БД. Он не считает метрики.
2. **Динамический расчет**: API (`src/lib/`) при запросе вытягивает сырые данные за период и динамически (или через материализованные представления) высчитывает VR, ERR, EP.
3. **Безотказность воркера**: Сборщик построен по принципу изоляции. Ошибка при парсинге одного канала (бан, изменение ID, таймаут) не роняет общий цикл, а только логируется и пропускает канал.

## Демография аудитории

`src/worker/demographics.ts` дополняет основной сбор отдельным еженедельным заданием.
Обрабатываются активные каналы с `isMine: true` и `type: channel`, у которых нет
успешного снимка за текущую неделю (с воскресенья, 00:00 в часовом поясе worker).
Так небольшая разница во времени завершения соседних запусков не приводит к
пропуску целой недели. Повторный параллельный запуск в одном процессе
пропускается; несколько экземпляров worker требуют отдельной координации.

Перед запросом проверяется `ChannelFull.canViewStats`. `GetBroadcastStats` и
`LoadAsyncGraph` направляются в `statsDc` без переключения основного клиента.
Отсутствие прав, недостаток статистики, ошибки графика и отдельного канала
не увеличивают `consecutiveErrors` и не прерывают обычный сбор. Используются
существующие ограничения частоты, обработка FLOOD_WAIT и таймауты.

Расписание `DEMOGRAPHICS_CRON` по умолчанию — `0 3 * * 0` (воскресенье, 03:00
в часовом поясе процесса). Некорректное значение заменяется этим расписанием с
предупреждением. Успешный снимок ограничивает сбор одним разом за календарную
неделю; недоступная статистика не создаёт пустой снимок.

Языковые доли рассчитываются по последней общей временной точке графика.
Повреждённые, несогласованные и нулевые данные пропускаются. География подписчиков
не предоставляется `stats.getBroadcastStats`: `countryBreakdown` остаётся SQL NULL.
Язык не используется для определения страны. Это ограничение также отображается
в карточке «Мой канал», вместе с датой снимка и отметкой данных старше недели.

Миграция `20260916213000_add_demographics_country` добавляет nullable JSONB-колонку
без изменения существующих снимков. Перед запуском обновлённого worker необходимо
выполнить `npm run prisma:migrate` в целевом окружении и пересобрать приложения.

Источники: https://core.telegram.org/api/stats и
https://core.telegram.org/constructor/stats.broadcastStats.
