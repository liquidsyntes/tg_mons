## 1. Цель и контекст

Приложение отслеживает пул Telegram-каналов/групп (конкуренты, референсы) и сравнивает их с одним базовым («Мой канал»). Система периодически собирает статистику, сохраняет историю в PostgreSQL и отображает минималистичный дашборд со сравнительными метриками.

**Ключевой сценарий:** открыть дашборд и за 10 секунд оценить:
- кто растёт быстрее «моего канала»;
- кто сколько публикует;
- текущую позицию «моего канала» на фоне конкурентов.

### Термины и определения
- **Канал** — публичный/приватный broadcast-канал или супергруппа. Обрабатываются единообразно (методы MTProto `channels.getParticipants` и `channels.getFullChannel` работают для обоих типов).
- **Мой канал** — канал с флагом `is_mine = true`. Ровно один в системе. Задаётся в конфигурации и может быть переназначен через UI/API.

## 2. Функциональные требования

### FR-1. Управление списком каналов
- **Добавление канала:** по `@username`, ссылке `t.me/...` или инвайт-ссылке (для приватных — только если сборщик уже состоит в канале).
- **Деактивация сбора:** включение/выключение мониторинга без удаления истории (`is_active: boolean`).
- **Удаление канала:** удаление из активного мониторинга с сохранением накопленных исторических данных.
- **Статус сбора:** наглядная индикация (`успешно` / `ошибка` / `давно не обновлялся`).

### FR-2. Собираемые метрики (периодичность сбора)

| Метрика | Источник (MTProto) | Периодичность |
| :--- | :--- | :--- |
| **Количество участников** | `channels.getFullChannel` → `participants_count` | Каждый час |
| **Посты** (ID + дата публикации) | `messages.getHistory` (инкрементально по `min_id`) | Каждый час |
| **Метаданные** (название, аватар, описание) | `channels.getFullChannel` | 1 раз в сутки |

### FR-3. Вычисляемые метрики (расчёт на лету из БД)
1. **Динамика участников (Δ за 24ч / 7д / 30д):**
   $$\Delta = \text{members\_now} - \text{members\_at}(\text{now} - \text{period})$$
   Где `members_at` — ближайший снапшот не позже границы периода. Отображаются абсолютное значение и процент изменения.
2. **Количество постов (за 24ч / 7д / 30д):**
   `COUNT(posts WHERE published_at >= now - period)`
3. **Средняя частота публикаций:** среднее число постов в день за последние 30 дней.
4. **Недостаток данных:** если канал добавлен недавно и истории на выбранный период нет — выводить `н/д` вместо `0`.

### FR-4. Сравнение с «моим каналом»
Для каждого отслеживаемого канала относительно «моего канала» рассчитываются:
- **Доля аудитории:** например, `1 240 подписчиков = 62% от моего`.
- **Разница темпов роста:** например, `+4.2% за 7д против моих +1.8%`.
- **Разница публикационной активности:** например, `12 постов / 7д против моих 5`.
- **Визуальный акцент:** «Мой канал» всегда закреплён первой строкой в таблице и выделен в графиках.

## 3. Сбор данных (Telegram MTProto)

### Архитектурное решение
- Telegram Bot API **не подходит**: метод `getChatMemberCount` доступен только для чатов с участием бота, а чтение истории постов чужих каналов через Bot API невозможно.
- Сбор выполняется через **MTProto user-клиент** (`api_id` + `api_hash` с [my.telegram.org](https://my.telegram.org), авторизация по номеру телефона, сохранение session-строки в `.env`).

### Требования к фоновому сборщику (Worker)
- **Изоляция:** отдельный фоновый процесс (Node.js worker), не блокирующий веб-сервер.
- **Расписание:** запуск по крону (`node-cron`), график задаётся через переменную `COLLECT_CRON` (по умолчанию: `0 * * * *` — каждый час).
- **Инкрементальный сбор постов:**
  - Хранить `last_message_id` для каждого канала.
  - Запрашивать историю строго с `min_id = last_message_id`.
  - При первом добавлении канала выполнять первичный бэкфилл глубиной в 30 дней.
  - Дедупликация постов по уникальному ключу `(channel_id, message_id)`.
- **Контроль лимитов и отказоустойчивость:**
  - Обработка `FLOOD_WAIT_*`: корректное ожидание с экспоненциальным backoff и джиттером.
  - Глобальный rate limit: ~1 запрос в секунду.
  - Последовательный обход каналов (без параллельного спама запросами).
  - Изоляция ошибок: если канал забанен, переименован или недоступен — записать ошибку в `last_error`, сохранить статус и продолжить обработку остальных каналов.
- **Логирование:** логировать каждый цикл сбора (канал, длительность, статус, количество собранных постов/снапшотов).

## 4. Архитектура и стек технологий

### Стек

| Уровень | Технологии |
| :--- | :--- |
| **Frontend + API** | Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui, Recharts |
| **База данных** | PostgreSQL + Prisma ORM |
| **Коллектор** | Node.js worker + gramjs (MTProto). *Допустимая альтернатива: микросервис на Python + Telethon* |
| **Инфраструктура** | Docker Compose (`web`, `worker`, `db`), конфигурация через `.env` |

### Схема базы данных (Prisma)

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model Channel {
  id              Int        @id @default(autoincrement())
  username        String?    @unique
  tgId            BigInt?    @unique
  title           String
  type            String     // "channel" | "group"
  isMine          Boolean    @default(false)
  isActive        Boolean    @default(true)
  lastMessageId   BigInt?
  lastError       String?
  lastCollectedAt DateTime?
  createdAt       DateTime   @default(now())
  snapshots       Snapshot[]
  posts           Post[]

  @@map("channels")
}

model Snapshot {
  id           Int      @id @default(autoincrement())
  channelId    Int      @map("channel_id")
  membersCount Int      @map("members_count")
  collectedAt  DateTime @default(now()) @map("collected_at")
  channel      Channel  @relation(fields: [channelId], references: [id], onDelete: Cascade)

  @@index([channelId, collectedAt])
  @@map("snapshots")
}

model Post {
  id          Int      @id @default(autoincrement())
  channelId   Int      @map("channel_id")
  messageId   BigInt   @map("message_id")
  publishedAt DateTime @map("published_at")
  views       Int?
  channel     Channel  @relation(fields: [channelId], references: [id], onDelete: Cascade)

  @@unique([channelId, messageId])
  @@index([channelId, publishedAt])
  @@map("posts")
}
```

> **Правило работы со временем:** все даты сохраняются в UTC. Отрезки «24ч / 7д / 30д» вычисляются относительно текущего времени (`now() - interval`), а не календарных суток.

### Спецификация API (Route Handlers)

| Метод | Эндпоинт | Назначение |
| :--- | :--- | :--- |
| `GET` | `/api/channels` | Список каналов с последними метриками |
| `POST` | `/api/channels` | Добавить канал (resolve username → `tgId`, запуск бэкфилла) |
| `PATCH` | `/api/channels/:id` | Переключить активность (`isActive`), назначить «моим каналом» (`isMine`) |
| `DELETE` | `/api/channels/:id` | Отключить канал от мониторинга |
| `GET` | `/api/stats/overview` | Сводная аналитика для главной: каналы, дельты, сравнение с моим |
| `GET` | `/api/stats/channel/:id?period=7d` | Таймсерии для графиков (динамика подписчиков, посты по дням) |
| `POST` | `/api/collect/run` | Ручной триггер цикла сбора (защита секретным Bearer токеном) |

## 5. Интерфейс и UX (Дашборд)

### Дизайн-система
- **Тема:** Тёмная тема по умолчанию, чистый минимализм, выразительная типографика, достаточное свободное пространство (воздух).
- **Цвета:** 1 акцентный цвет бренда + семантические цвета дельт (зелёный — рост, красный — спад).
- **Типографика:** моноширинные/табличные цифры (`tabular-nums`) для числовых колонок.
- **Отказ от визуального шума:** минимум лишних рамок, теней и декоративных плашек.

### Структура страниц

#### 1. Главная страница (Overview)
- **Хедер / Верхний блок:** крупная карточка «Мой канал» (текущие подписчики, Δ за 24ч / 7д / 30д, количество постов за 24ч / 7д / 30д).
- **Сравнительная таблица каналов:**
  - Название и юзернейм канала
  - Текущие участники
  - Динамика (Δ 24ч / 7д / 30д с цветовой индикацией и стрелками)
  - Количество постов (24ч / 7д / 30д)
  - Относительная колонка «% от моего»
  - Сортировка по любому столбцу
  - «Мой канал» всегда закреплён первой подсвеченной строкой.
- **Адаптивность:** на экранах мобильных устройств таблица плавно перестраивается в компактные карточки.

#### 2. Детальная страница канала
- **График участников:** линейный график (Line Chart) за 30 дней.
- **График активности:** столбчатая диаграмма (Bar Chart) распределения постов по дням.
- **Интерактивность:** переключатель периодов (24ч / 7д / 30д).
- **Сравнение:** тумблер наложения кривой «моего канала» на график.

### Состояния интерфейса (UI States)
- **Loading:** скелетон-анимации (Skeleton) вместо спиннеров.
- **Empty State:** экран приветствия с призывом добавить первый канал для отслеживания.
- **Error State:** информативное отображение текста ошибки при сбое сбора данных.

## 7. Критерии приёмки

- [ ] **Добавление канала:** при вводе `@username` в течение 1 часа подтягиваются участники и история постов; через 24 часа доступна корректная суточная дельта.
- [ ] **Точность вычислений:** дельты и счётчики публикаций совпадают с прямыми SQL-запросами к базе данных (допустимо расхождение ±1 пост на границе временного окна).
- [ ] **Отказоустойчивость:** ошибка сбора по одному из каналов (бан, Flood Wait) не прерывает работу воркера и отображается в UI.
- [ ] **Сравнительный анализ:** для каждого канала корректно рассчитываются относительные проценты и разницы с «моим каналом».
- [ ] **Развёртывание:** проект полностью поднимается и работает по команде `docker compose up` без ручных правок кода.

## 8. Ограничения и риски

1. **Приватные каналы и группы:** сбор возможен исключительно при условии, что Telegram-аккаунт сборщика предварительно вступил в данный чат/канал.
2. **Лимиты Telegram (Flood Wait):** частые запросы к MTProto могут вызвать временную заморозку сессии. Обязательны rate limiting (~1 rps) и корректная пауза при `FLOOD_WAIT_*`.
3. **Дискретность метрик:** динамика подписчиков рассчитывается на основе периодических снапшотов (точность зависит от частоты выполнения крона).\n
