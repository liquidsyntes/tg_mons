# Оценка распознавания событий

Набор `synthetic-v1`: 80 синтетических русскоязычных публикаций, 10 категорий по 8 примеров. Это стартовая проверка сценариев на шаблонах с разными названиями, а не репрезентативная выборка Telegram. Реальных сообщений и персональных данных нет. 50 примеров calibration, 30 control; связанные объявления не пересекают части. Шаблоны категорий присутствуют в обеих частях, поэтому контроль проверяет устойчивость к вариантам, а не обобщение на новый стиль текста.

## Разметка

Положительный пример приглашает на одно событие с определимой датой и условиями участия. Отчёт, подборка, неопределённая дата и тизер без деталей отрицательны. Относительные даты разрешаются относительно `publishedAt` в `timeZone`. Для примеров перехода года 31 декабря 21:30 UTC соответствует 23:30 Europe/Kyiv, «завтра» означает 1 января. `duplicateGroup` объединяет только одно событие; сеанс в другое время является отдельным событием.

`expected.event` задаёт канонические поля. Проверка полей сейчас строгая: альтернативная корректная формулировка названия будет отмечена расхождением и требует просмотра. Это ограничение метрики, не доказательство неверного извлечения.

## Команды (из корня проекта)

```bash
npx tsx scripts/evaluate-events.ts evaluate --dataset src/lib/events/eval-data/dataset-v1.json --run src/lib/events/eval-data/jev-baseline.json --split control --out /tmp/jev-report.json
npx tsx scripts/evaluate-events.ts compare --dataset src/lib/events/eval-data/dataset-v1.json --run src/lib/events/eval-data/jev-baseline.json --other src/lib/events/eval-data/gemini-baseline.json --out /tmp/comparison.json
```

Выходной файл должен отсутствовать. Для повторного запуска используйте новое имя. Результат evaluation детерминирован для одинаковых входов. `split` необязателен. Разные хеши набора и разные split сравнивать нельзя. Нулевой знаменатель даёт null; ошибки модели учитываются отдельно и не становятся отрицательным решением. Coverage показывает долю решений без ошибок. `costUsd` и latency относятся ко всему сохранённому прогону, даже при фильтре split; неизвестная стоимость остаётся null.

Отбор включает production-фильтр явных дайджестов. Keyword fallback оценивается отдельно. Для извлечения можно передать `--extraction path.json`: объект `{ "provenance": "live" или "synthetic", "events": [...] }`, где событие содержит `title`, календарную `date`, nullable `timeStr`/`organizer`, `prices: string[]`, `sourcePostIds: number[]`. Исходные ID сверяются с набором. Без ответов извлечения весь раздел extraction равен null, а не идеальному результату. Дедупликация использует production `isSameEvent`, без обращения к БД. Сравнение показывает изменившиеся ошибки полей и показатели дублей.

Платный сбор ответов Decisions, без автоматических повторов:

```bash
npx tsx scripts/evaluate-events.ts capture --dataset src/lib/events/eval-data/dataset-v1.json --model google/gemini-decision-1 --allow-paid yes --limit 80 --out /tmp/gemini-run.json
```

Требуется `OPENROUTER_API_KEY` в окружении. CLI не читает SystemSetting, не открывает БД и не запускает API сканирования. `--limit` обязателен, диапазон 1-100, пакет 10, последовательные запросы, timeout 30 секунд. Ошибка сохраняется без тела ошибки провайдера и без ключа. Ответы сохраняются после каждого запроса; повторный запуск на тот же файл запрещён. Файл `.requests.json` сохраняет точные вопросы и состав пакетов. Для другой модели заменить `--model` на `~typesafe/jev-latest`. Генеративные запросы этот CLI не выполняет.

## Baseline от 16 ноября 2026

Два настоящих прогона Decisions по 80 примеров с одинаковыми вопросами и порогами, по 8 запросов. `*-baseline.json` содержит ответы и usage, `*-requests.json` точные запросы. Идентификаторы запросов провайдера удалены перед включением в Git; содержимое решений сохранено. Модели-алиасы могут меняться, фактическое поле model сохранено в ответе. Никаких автоматических повторов не было.

| Модель | TP | FP | FN | TN | Recall | Медиана пакета | Стоимость полного прогона USD |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Jev | 34 | 0 | 14 | 32 | 70.83% | 356 мс | 0.00181839 |
| Gemini Decision 1 | 34 | 0 | 14 | 32 | 70.83% | 479 мс | 0.00638630 |

На control: Jev 12/18 анонсов, Gemini 14/18, ложных срабатываний нет. Jev распознал 8/8 онлайн-анонсов, Gemini 0/8; относительные даты 2/8 против 7/8. Нельзя переносить эти цифры на реальные каналы. Пороговая калибровка не выполнялась, основной моделью остаётся Jev.

Объединение независимых решений по OR даёт 44/48 (91.67%), по AND 24/48 (50%), FP=0. Это offline-оценка потенциального каскада: настоящий последовательный прогон с Gemini только на отказах Jev ещё не выполнялся; другой состав пакетов способен изменить ответы. Автоматический каскад в production не включён.

Генеративное извлечение на живой модели не запускалось. Его качество и влияние часового пояса на ответы модели пока не измерены. Фикстуры unit-тестов проверяют работу оценщика и не заявляются качеством генеративной модели.

`prepare-extraction --dataset ... --run ... --out ...` формирует промпт из выбранных примеров через тот же `buildExtractionPrompt`, что API. Сохраняет хеш набора, decision-прогона и промпта. Дата публикации и часовой пояс передаются явно. Команда не вызывает генеративную модель. Полученный ответ можно передать evaluator через `--extraction`; сведения о модели извлечения и использованном промпте следует хранить рядом с ответом.

## Настоящая перепроверка отказов (#89, 16 ноября 2026)

Первая ступень использует сохранённый live `jev-baseline.json` без повторного платного вызова Jev. Вторая ступень действительно отправила только 46 отрицательных решений Gemini, новыми пакетами 10/10/10/10/6. Ответы в `gemini-cascade.json`, точные запросы в `gemini-cascade-requests.json`, итог в `cascade-report.json`. Пять запросов без ошибок и автоматических повторов.

Результат: TP=44, FP=1, FN=4, TN=31; precision 97.78%, recall 91.67%. На control: TP=16, FP=0, FN=2, TN=12. Перепроверка восстановила 10 пропущенных Jev анонсов, но добавила одно ложное срабатывание. Состав восстановленных примеров отличается от независимого OR. Стоимость новой ступени $0.00364540, с исходной ступенью Jev $0.00546379. Затраченная сейчас сумма включает только новую ступень.

```bash
npx tsx scripts/evaluate-events.ts capture --dataset src/lib/events/eval-data/dataset-v1.json --model google/gemini-decision-1 --allow-paid yes --limit 80 --rejected-by src/lib/events/eval-data/jev-baseline.json --out /tmp/gemini-cascade.json
npx tsx scripts/evaluate-events.ts cascade --dataset src/lib/events/eval-data/dataset-v1.json --run src/lib/events/eval-data/jev-baseline.json --other src/lib/events/eval-data/gemini-cascade.json --out /tmp/cascade-report.json
```

`--rejected-by` проверяет полноту первой ступени и хеш набора до сети, сохраняет parentRunHash. `--limit` ограничивает количество отказов для перепроверки. Отсутствующий ответ второй ступени остаётся неизвестным; успешное принятие первой ступени сохраняется. Оценка запрещает несовпадающий родительский хеш и посты, которых не было среди отказов. Production-каскад не включён: для его введения нужно определить обработку отказа второй модели и проверить ложные срабатывания на более разнообразной выборке. Настоящий эксперимент всё ещё использует маленький шаблонный набор.
