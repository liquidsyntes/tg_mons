## Разбивки и воспроизведение

report.json содержит общую, calibration/control, языковую и категорийную сводки, ID ошибок и изменённых решений, известные расходы/длительности каждого прогона. Поле extraction равно null: извлечение не измерялось.

Из корня проекта (выходной файл должен отсутствовать):

```bash
npx tsx scripts/evaluate-events.ts evaluate --dataset src/lib/events/eval-data/dataset-v2.json --run src/lib/events/eval-data/live-v2/jev-original.json --out /tmp/jev-v2-replayed.json
npx tsx scripts/evaluate-events.ts evaluate --dataset src/lib/events/eval-data/dataset-v2.json --run src/lib/events/eval-data/live-v2/gemini-original.json --split control --out /tmp/gemini-v2-control-replayed.json
npx tsx scripts/evaluate-events.ts cascade --dataset src/lib/events/eval-data/dataset-v2.json --run src/lib/events/eval-data/live-v2/jev-original.json --other src/lib/events/eval-data/live-v2/cascade.json --out /tmp/cascade-v2-replayed.json
```

Точные payloads находятся в *.requests.json; их хеши для шести независимых прогонов сверяются с ../manifest-v2.json. До публикации response.id провайдера удалены. Ответы, usage, model и durationMs сохранены. В cascade.json parentRunHash обновлён на хеш очищенной первой ступени; исходный parentRunHash в плане запросов и originalHash/publishedHash в report.json фиксируют преобразование. Это санитизация артефактов, не повтор платных вызовов. capture-source.txt сохраняет фактически использованную обвязку (пути /app относятся к контейнеру); её не надо запускать для воспроизведения отчёта. Обвязка прекращала новые реальные запросы при неизвестной стоимости, 140 запросах или известных расходах >=$0.90. Денежная остановка между запросами не является жёстким лимитом цены уже отправленного запроса.

## Ограничения и рекомендация

50 базовых семейств, по четыре зависимых языковых/редакционных варианта. В control только 24 независимых семейства. Расширения имеют общий редакционный абзац, тексты искусственные, даты/время сконцентрированы, разметка выполнена одним автором без независимого рецензента. Результат не оценивает реальное распределение Telegram и не подтверждает статистическую надёжность нулевого FP. Decisions не получает publishedAt/timeZone. Модели указаны aliases, фактические model/provider сохранены в ответах. Пороговые решения не подгонялись.

Рекомендация: оставить одну модель Jev. Каскад на этом наборе восстановил 12 пропусков, но контрольный критерий прироста не выполнен; зависимость ответов от пакета подтверждена наблюдаемыми различиями. Для следующего решения нужна отдельная более разнообразная проверка с независимой разметкой и повторными измерениями. Внедрение каскада не предлагается как готовое по этим результатам.
