# TgMon — карта проекта

Состояние исходников сверено 20 октября 2026 года. Основной checkout: `C:\TgMon` / `/mnt/c/TgMon`. Репозиторий: `liquidsyntes/tg_mons`. Локальный web: [localhost:4000](http://localhost:4000).

## Назначение

Мониторинг и сравнение Telegram-каналов и групп: история аудитории, метрики публикаций, рекламная нагрузка, цитирование, эвристические сигналы риска и AI-анализ собранного контента.

## Устройство

- Next.js App Router, React и TypeScript: страницы/API в `src/app/`, UI в `src/components/`.
- Расчёты и запросы: `src/lib/`; Prisma-схема и миграции: `prisma/`.
- PostgreSQL хранит каналы, посты, ограниченные по размеру изображения постов, снимки, дневные агрегаты, упоминания, события, сигналы, демографию и отчёты.
- Отдельный worker в `src/worker/` использует teleproto через npm alias `telegram`; расписание, сбор и сохранение отделены от UI. На сервере worker использует `TG_SESSION` и запускает расписания cron; локально (`npm run worker:local` / `bash dev-web.sh`) он использует строго отдельную сессию `TG_SESSION_LOCAL` в режиме по запросу (без cron), исключая `AuthKeyDuplicated`.
- Локально проект запускается нативно (`bash dev-web.sh` в WSL), а на сервере OVH (`ovh-vps`, `/opt/tgmon`) — в полном Docker-стеке (`postgres`, `web`, `worker`) через `bash update.sh`.

## Текущие возможности и ограничения

- ER/ERR/VR, CR групп, EP, Content Score, Ad Load и Citation Index; формулы и окна различаются по источникам.
- Антифрод: четыре эвристики, сохранение FraudSignal и аудит при чтении; балл риска не является вероятностью накрутки.
- Статьи Telegram преобразуются в обычный текст для просмотра, поиска и анализа. Частичные статьи догружаются, старые пустые записи восстанавливаются отдельной утилитой.
- Демография ограничена языковой статистикой при наличии прав; география не выводится из языка.
- AI использует OpenRouter и сохранённые тексты. Настройки провайдера/модели в UI пока не управляют фактическим клиентом; старые отчёты не обновляются после восстановления контента.
- Архив AI-отчётов поддерживает HTML-экспорт и физическое удаление записи после подтверждения. «Афиша» показывает сохранённые изображения постов, когда они доступны.
- Web UI поддерживает многопользовательский режим с регистрацией по инвайтам (`InviteCode`), персональными списками каналов (`UserChannel`), ролями `ADMIN`/`USER` и резервным входом по `COLLECT_API_TOKEN` (подписанная `HttpOnly`-cookie `v2`/`v1`). У `worker` остаётся `Bearer`. Ключ OpenRouter общий и управляется администратором.
